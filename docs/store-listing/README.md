## 1. Store fields — what the code says

The owner's field list (creation form A, then logo / main image / cover / gallery / EN+ZH Markdown description)
is the structure of every product file. Where the code says more or differs:

**Creation form** — `PrimeForge-Server/apps/console/app/products/new/page.tsx:116-233`; hints in
`packages/i18n/messages/en.json` (`console.products.new.form.*`, e.g. `kindHint` :592, `priceHint` :571).
Product ID (optional, derived by `deriveProductId`, `apps/api/src/admin/core/product-request.ts:54-62`) · Kind
(app / addon, set once) · App ID * · Name * · Description · Price (GBP pence) * · Payment channels · Billing ·
Stripe price ID · Renewal interval.
- `deriveProductId` uses only the **last** segment of the app id, so a blank id for
  `app.primeforge.mathviz.python` becomes `python-buyout`. I suggest explicit `mathviz-<t>-buyout` /
  `mathviz-<t>-addon-buyout` ids (suggestion, not a decision).
- The form's Description box writes the product's **English content description**, not a separate field
  (`apps/api/src/store/admin-api.ts:254-257`); it is overwritten when B3 is pasted into Content.

**Content editor** (the listing) — `apps/console/app/products/[id]/content/content-editor.tsx:36-39,243-407`,
hints `en.json:1294-1325`:

| Field | Limits |
|---|---|
| Name | 1–200 chars, **one value** (no Chinese name field) |
| Icon | PNG, exactly 512 × 512, ≤ 2 MB, nothing resized; SVG refused (`:1296`, `error.svg_refused`) |
| Main image | PNG/JPEG/WebP, exactly 16:9, 1280 × 720 to 3840 × 2160, ≤ 10 MB (`:1325`); shown in featured slots |
| Gallery | ≤ 30 items; images PNG/JPEG/WebP ≤ 10 MB, MP4 ≤ 200 MB (`:1302`) |
| Description EN / 中文 | Markdown, ≤ 20,000 chars per language; either may be empty and the store shows the other (`:1311`) |
| Quick start EN / 中文 | Markdown, ≤ 20,000 each; "shown after purchase and on the store page", empty hides it (`:1317`) |

- **There is no cover field.** The cover is the **first gallery image** (`apps/store/lib/shelf.ts:74-79`,
  `cardPictureOf`), and the product-page carousel leaves it out. Upload the cover first.
- **There is no summary field.** The store card's excerpt is the description's first paragraph cut at 200
  characters (`apps/store/lib/description.ts:22,50`); the Desktop add-on row's `summary` / `summaryZh`
  (`PrimeForge-Desktop/packages/platform-service/src/store-client.ts:212-216`) are the first paragraph cut at
  280 (`PrimeForge-Server/apps/api/src/store/addon-list.ts:32-35,59-84`) — **only for an add-on-kind product**;
  an add-on sold only through a bundling app product shows its `addon.json` title and no summary
  (`addon-list.ts:169-174`). Every first paragraph here is ≤ 200 in both languages.
- **Quick start** is in the code but not in the owner's list: written for the four apps as optional B5.
  Math Test Buddy's `docs/store/listing.md` says the field "takes one text"; the current editor has one per
  language (`content-editor.tsx:75-76,400-407`). **I followed the code** and wrote two.

**Product page, after creation** (`apps/console/app/products/[id]/page.tsx:232-373,560-641`): Category (at most
one, from Console → Categories; slug ≤ 40, names ≤ 60), Price/Billing as a versioned draft, Trial days
(subscriptions), Listing (listed / withdrawn), Visibility (Public / Unlisted / Restricted), **Unlocked add-ons**
(ticks), and an account list for Restricted products.

**Not in the store at all** (searched the store, console and API): age rating / audience, support URL, privacy
URL, tags/keywords, developer/publisher field, per-language name. Nothing to fill.

**Order the platform imposes** (`PrimeForge-Desktop/docs/build-manual.md:880-1070`): `publish:app` (into the
signed catalogue) → create the app product → `build:mathviz-addon <t>` + `publish:addon` (refused until the app
is in the catalogue) → create the add-on product and tick `<appId>/content` under Unlocked add-ons → fill
Content → Publish. Add-ons are not in the catalogue; their product lives only in the console.

## 2. Copy rules followed

## 4. Assumptions

- Names: the store name is the manifest's English name; the Chinese names in `target.json`
  (e.g. "Viz Learn Buddy · Python 练习") are in-app only, because the store has one name field.
- Content packs get their **own add-on-kind products** (so the Desktop row and in-app *In the PrimeForge store*
  card show a real name, summary and icon) rather than being bundled under the app product.
- Pack names "Viz Learn Buddy for <Subject>: Content Pack"; the app calls it a "content pack" / 内容包 everywhere.
- Listed versions: apps 1.0.0 (manifests; python 1.0.1 after a same-version reinstall, math 1.0.2 for the recorder, chess 1.0.1 for its stepper pages), first pack version 1.0.0 with `minAppVersion` = the app's version when the pack is built (build manual).
- "PrimeForge Desktop 1.45.0 or newer" from `minDesktopVersion`; no OS is named because nothing at hand states
  which platforms the MathViz apps are released for.
