## 一、地基阶段（PR-A #172 · PR-B #173 · #174）

### R1

构建者**自己**在 `python-tools.json` 追加本页注册表条目（文案可为草稿），连同重新生成的两个导航页
一起提交；原分工「不碰注册表，文案写进报告、由控制方集中登记」作废。 — 理由：`build_programs.py`
在工具页没有注册表条目时硬错误退出，`page_mirror_check` / `registry_check` 也要求条目存在——
照原分工，构建者一道门都跑不绿（地基终审 G2）。 — 代价：并行构建者的注册表与 FALLBACK 必然冲突；
解法是机械的「取集成分支版本 + 补回本页条目 + 重跑生成脚本」，两波共 6 次冲突全部这样解掉，零次手工合并。

### R2

新增六道门（`sync_fallback --check` · `page_mirror_check` · `blank_presence_check` ·
`line_note_reader_check` · `closed_set_mirror_check` · `js_parser_parity_check`），其中最后一道
是终审时追加、不在原计划里的。 — 理由：提示里一个 U+2028 就能让三种模式全部崩溃，而当时 39 道门全绿
（地基终审 G3）。 — 代价：门数 34 → 40；`check.py` 已按组自数，散文里不写门数，所以加门不会带来漂移。

### R3

`lines` 不含 BLANK 指令行，也不含文件末尾换行产生的空尾巴；按 `\n` 切，不认 U+0085 / U+2028 / U+2029
（Task 11c、G3）。 — 理由：页面显示的行数与「不超过 N 行」筛选都该与学生看到的程序一致。
— 代价：带空的程序 `lines` 数字变小，画廊卡片上的数字与改动前的缓存副本不同（版本号即缓存键，随发布自然刷新）。

### R4

挖空反馈在期待的 token 是字符串 / f-string 时只报类别与第几个字符起不同，绝不印字面量原文（Task 11b）。
— 理由：原来一个 f-string 空点一次「检查」就能看到整行答案。 — 代价：学生靠试错定位字面量里的错字更慢；
波 1 终审由此发现「字面量只能从输出得知」的一类空（见 R8），它的根源正是这条加上「页面不显示输出」。

### R5

注册表与 FALLBACK 的比较把**类型**也算进去（`b2c8d37`）。 — 理由：`"1"` 与 `1` 在 JSON 里不同，
在 JS 的 `==` 下相同；只比值的门会放过一个会让 `module` 分组静默失效的错。 — 代价：无已知。

### R6

装饰器配色选 `#bef264`，选色协议是可测量的：排除「错」用的 rose 色系，对同屏所有文字色算
CIEDE2000 ΔE 并要求对比度达标；`PyLex.TYPES` 闭集配测试，每个 token 类型要么有配色、要么显式列为不上色。
— 理由：第一版选色（`0667b81`）落在「错」色系里，由 `3774df1` 改掉。 — 代价：若你觉得不好看，改色只需过同一协议。

### R7

行注读取点门从「行级 grep」改为「单词级白名单」，STR 里只认键声明，`t(` 不认成员调用，门的威胁模型与
盲区写进文件头（`f17b92e` · `6b15250` · `0696101`）。 — 理由：前两版分别漏抓解构 / 模板键和误认成员调用。
— 代价：白名单是结构性的，将来 core 出现第四种合法读取形状时门会红，需要人判断后加进白名单。

## 二、波 1（#175：py-strings / py-functions / py-oop / py-files-errors）

### R8

**6 个空的最后一级提示直接给出字面量文字**（password-rules 两处、docstrings-and-type-hints 的整句文档串——
该空由 level 1 改为 2、positional-keyword-default 的 `"Hello"` 与 `"!"`、inheritance-and-super 的
`, studies at `、str-and-repr 的 `pages`）。 — 理由：页面不显示程序输出，这些文字只在输出里出现，
学生只能逐字符试错或切到读模式抄。 — 代价：最后一级提示更接近答案；但提示只给文字、不拼出整行。

### R9

`password-rules` 保留「标志位逐条检查」，尽管设计 §6.5 把标志位划给 py-loops。 — 理由：§7.1 是逐条审过的
清单，比 §6.5 的概括表更具体；终审同意，并建议把例外写回规格——已写（§6.5 表后注记），并列出同类的
`mutate-vs-return` / `mutable-default-trap` / `class-vs-instance-attributes`。 — 代价：py-loops 讲标志位时
必须换题（波 2 已照做，终审确认未重复）。

### R10

`local-and-global-scope` 只打印 `type(error).__name__`，不打印 UnboundLocalError 的消息。 — 理由：消息在
3.9.6 与 3.12.9 上实测不同，学生本机不一定是 CI 的 3.12。 — 代价：输出少一句解释，由讲解补上。
（构建者担心的 `int()` ValueError 文案在 3.9–3.12 上实测逐字相同，未改——这是简报的事实错误之一。）

### R11

`try-except-else-finally` 的 `else:` / `finally:` 两个空各扩成「子句行 + 下一行 print」，改为 level 2。
— 理由：原来下一行 print 就写着答案，几乎不用回忆。 — 代价：两行空要求学生打出 print 的字面量，
按 R8 在最后一级给出；复审实测缩进由 Enter 自动补，不会被坑。

### R12

`@abstractmethod` 那个空保留，尽管答案在 import 行里可见。 — 理由：`from abc import ABC, abstractmethod`
是程序必需的一行，挖不掉也改不掉。 — 代价：这个空形同抄写；记账（账本 §四「内容（小）」）。

### R13

`boards` 四页全保留四家考试局，**等你裁决语义**。 — 理由：规则是「确知某考纲不含才去掉」，评审员查不到
任何能确证排除的证据（唯一找到的 Pearson GCSE PLS 不含 try/except，那是 GCSE 不是 A-level）。
— 代价：若你裁定 `boards` 应表示「考纲点名」，M1 与 M2 八页要大面积改（`@dataclass`、ABC、
`*args/**kwargs`、`lambda`、`for…else` 等没有一家 A-level 考纲点名）。

### R14

「复制进 PyCharm 缺 `_fixtures/`」本波不做结构方案，只在讲解末段手抄文件位置与内容。 — 理由：结构方案
（加门或改复制内容）属于门或 core，不是内容波的范围；让程序自己先写出数据文件会改变 read-csv 的教学重点。
— 代价：四个程序的手抄与 `_fixtures/` 目前无门守一致（账本 §一.2）。

### R15

规格 §8.4 第 3 条写「`file://` 打开」，控制方改用 http 预览打开 worktree 路径，探针第一步断言读到的是本分支
（worktree 标记文件 + `TOOL.id`）。 — 理由：浏览器工具不能操作 `file://`；而预览服务器的根是主工作区，
直接开根路径测到的是别的分支的旧文件。 — 代价：`file://` 下的行为（例如 clipboard 降级路径）没有被机器验证，
留给你双击验收（PR 里列为未勾选项）。

### R20

（`year % 400 in frozenset(range(0, 400, 4)) - {100, 200, 300}`）。 — 理由：3.12 的 `calendar.isleap`
源码与被测的那一行**逐字相同**（`inspect.getsource` 核对），违反「参照机制必须不同」；控制方最初提议的
`datetime.date(y, 2, 29)` 同样同源，且只接受 1–9999 年而生成器会抽到负年份——终审指出，改用余数集合。
在 −100000..100000 上与被测、与 `calendar.isleap` 均 0 处不一致（测量负控制：把 300 放回集合 → 500 处不一致）。
— 代价：无已知。**这是清单本身的事实错误**，已写回作者须知与终审简报（#178）。

### R21

三角形 `cases` 生成器以 1/4 概率专门构造正边长等边三角形。 — 理由：原生成器从不产生它，把 `"equilateral"`

### R22

不会念出整行，不适用作者须知的例外。 — 代价：第 1 级已说全，后两级反而更泛（复审 Minor，记账）。

### R23

de-morgan 的表头改为 `De Morgan's first law` / `second law`，讲解改用 ¬ ∧ ∨ 写定律。 — 理由：原表头改个
大小写就是两个空的答案。 — 代价：讲解第 1 段先用符号、第 3 段才释义（复审 Minor，记账）。

## 五、控制方自己的失误

照第 0 期的惯例单列。没有一条造成错误结论。分三类（账本 §五.4 同此分法）：**无效的红**——#1、#2、#7；
**假绿**——#3（一段没跑的检查看起来像跑过）；**文书与推理错误**——#4、#5、#6：

1. **复制真跑工具把 `_fixtures/` 里的文件平铺到临时目录根**，而程序读的是 `_fixtures/scores.csv`——
   两个 CSV 程序断言红，原因是工具与门的做法不同。改成与门一样 `copytree` 后复绿。这次误红恰好复现了
   「粘进 PyCharm 缺数据文件」的真实症状。
2. **zsh 不对 `set -- $p` 分词**，一轮复制真跑四次 IndexError 崩溃，rc=1 与断言失败同码。只能看 Traceback 区分。
3. **`| tail` 之后 `echo rc=$?`**：一次 payload 崩溃（把 ch06 的程序指给 ch08）被显示成 rc=0。
4. **不带引号的 heredoc** 把 PR 描述里的反引号当命令执行，吃掉了 CI 那一行，发现后重写。
5. **台账写「波 2 有 9 个页内变体组」**，实为 11 个——终审指出。
6. **R20 最初提议的 datetime 参照**同样同源——终审指出。
7. **浏览器探针首版**按标题全等找程序崩溃（列表项文字里含元数据）；**localStorage 复原比较**首版按插入顺序
   比 JSON 串，内容无残留却报 false。两者都在第一次运行时暴露并修掉，未产生错误结论。

## 六、子代理上报「简报有错」

两波共 8 个构建者、2 次终审、2 次范围复审、2 个修复实现者。经实测复核**成立**的上报：

- 页面不显示程序输出（波 1 终审）——简报与模板默认学生看得到输出。
- `int()` ValueError 文案跨版本不变（波 1 终审）——简报说它会变。
- 钩子脚本来自主工作区、但操作的是提交所在 worktree 的文件（波 1 两个构建者）——简报说「跑的是主工作区那份」。
- `calendar.isleap` 与被测同源（波 2 构建者）——清单 P 列错。
- `datetime` 替代方案同样同源（波 2 终审）——控制方的提议错。
- 变异应在导出副本上做（波 2 复审员）——简报做法破坏只读。
- `lru_cache` 裸形上限 128（波 2 构建者）——清单字面不准确。

没有一条被判为「上报者错了」。
