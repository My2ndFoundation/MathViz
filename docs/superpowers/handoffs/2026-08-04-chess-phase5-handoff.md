## 阶段 4 留给你的四件事（必须先处理，不是可选项）

### 1. `inline_core.py` 的 `ALGOS` 是整目录倾倒 —— 阶段 5 会让它变成六倍

`ALGOS` 现在把 `core/algos/*.js` **全部**内联进任何带 `GENERATED:ALGOS` 标记的页面。今天只有一个算法源码，所以看不出问题。

**你要加六个。** 那之后：工具④ 会带上六份它从不执行的算法，工具⑤ 会带上 `minimax.js`——每页约 60–100 KB 死负载，且随每个新算法增长。零依赖与 `file://` 不受影响，纯粹是浪费。

**在六个文件落地之前**决定标记语法（例如 `GENERATED:ALGOS:queens.js`，或一页一个清单），不要落地之后再回来改——那时要同时改六个页面。

### 2. `tree-model.js` 从带外属性读 `truncated`

`tree-model.js:589` 读的是 `view.trace.truncated`，而那是 `Interp.run` 挂在**数组对象上**的属性。实测：`r.trace.truncated === true`，但 `r.trace.slice().truncated === undefined`。

任何调用方只要拷贝或 `map` 一下轨迹再交给 `createView`，就会静默得到 `truncated: false`——而「**没跑完**」是工具④ 的中心一课，也会是工具⑤ 里朴素回溯撞上限时的中心一课。今天页面传的是活数组，所以没出事。

### 3. `pollDepth` / `ensureSweep` 每帧重试，没有失败闩锁

`chess/tools/chess-search-minimax.html`。两处都是「没达到终态就下一帧再来」，中间夹着约 235 ms 的同步解释器运行。**没找到可达的触发条件**（`buildTab` 接住了 `I.run`，`withDepth` 返回 `null` 而不抛，`withBusy` 在 `finally` 里复位），所以这是加固不是缺陷。

但阶段 4 验收时出现过**一次无法复现的整页卡死**（长脚本串跑），拆开重跑四次全过、未能归因，而上面这个形态是代码侧最像的机制。工具⑤ 如果照抄这套 tab 骨架，请连闩锁一起加。

### 4. 「面板角标读 meta」在 chess 引擎里不成立

规格 §10 说版本落三处、角标读 meta 所以不用单独改。**chess 的引擎读的是脚本常量**，不是 meta——工具① 的 1.0.2 changelog 记过这笔账，阶段 4 又踩了一次。`VERSION` 常量与 `tool-version` meta **必须一起改**。

## 阶段 3b–4 用血换来的判断（这些比计划本身更重要）

### 1. 「拿一个独立参照对拍」比任何手写期望值都值钱

这条在四个阶段里回报最高。具体形态：

- 树的父链与**运行时调用栈**逐项对拍（不是跟自己对）；
- 增量游标与**全量重建**逐点对拍，**正向反向都要**；
- α-β 与**纯 minimax** 对拍返回值——剪枝只许省搜索，不许改答案；
- 高亮片段拼回**原文**逐字节相同；
- `Editor.check` 与 `Interp.parse` 对拍：`check(src) === null` 当且仅当 `parse` 不抛。

### 2. 「测试全绿」经常只是「这条测试测不到它要测的东西」

阶段 4 里被抓到的：布局测试在「按节点平均分」的变异下**全绿**（它的三条断言对任何「不重叠 + 父居中」的布局都成立，与权重无关）；被称作命脉的增量对拍在「永远全量重建」的变异下**全绿**（它证明的是正确性，不是增量性）；截断轨迹上剪枝报 `null` 这件事**根本没有断言**，实现改成报一个编造的数字照样通过。

**每写一条重要断言，就改坏实现跑一次。** 绿的就是没牙的。

### 3. 「测量方法本身可能就是 bug」——这一条在阶段 4 中了三次

都是控制器自己犯的：

- 规格里公布的 make/unmake 数字**混了三个变量**（那份对照还缺走法编码与预计算表），把 +21% 说成了「差一整层深度」；
- 拿「57 个节点但 `Step.depth` 到 4」当作父子按栈判定的「铁证」——**它根本不能判别**：最深那一步是 `onBoard` 的入帧，而所有 57 个 `search` 入帧步上 `Step.depth` 恰好等于树深 +1，深度推断的变异在那条 fixture 上是**绿的**；
- 一次探针变异把生成源码改成了未闭合注释，于是「守卫失效」与「源码语法错」分不开。

**看到一个测量结果之前，先问它测的到底是什么。**

### 4. 视觉与交互缺陷，能读代码的东西抓不到

阶段 0–2 用户三次截图各抓一个多轮审核漏掉的问题；阶段 3b 截图抓到棋盘拖宽就被裁；**阶段 4 的浏览器验收当场抓到五个**：页签栏压住参数面板、`body.classList.add('busy')` 命中 `.busy{display:none}` 让整页消失且 `fit.s` 被量大 3.16 倍、深度 2 的分数标签糊成墨迹、点调用栈无反馈、窄屏三面板重叠。

**把「请你看一眼」当成正式验收环节。**

### 5. 公开导出的省略参数是一个反复出现的缺陷类

同一形态被抓到三次：`playSteps` 的 `cap` 缺席把累加器变成 `NaN` 并永久污染；`refresh` 静默推进 UI 基准；`TreeModel.seek(view)` 把游标**从 120000 悄悄倒回 0**（`undefined | 0 === 0`）。三处都已改成大声抛错，且与「`null` 表示不知道」严格区分——后者是合法的**数据**值，前者是**调用方的 bug**。

**工具⑤ 新增的每一个导出，都问一遍「少传一个参数会怎样」。**

### 6. 不许编造数字，不知道就说不知道

`null` 一路贯穿到面板显示 `—`：截断轨迹上剪枝不可判定、学习者把 `let ms` 改名后分支因子读不到、没记到返回值的节点没有值。同源纪律是 3a 拒绝编造「省略了 N 步」。

**推论：凡是把可数的事实抄进文案的地方，加东西时都要一起过。** 根页面的 chess 卡片就在阶段 4 之后写了两个月的「两个工具」，实际是四个。

## 环境事实（会浪费你时间的那些）

- **浏览器面板的 rAF 被节流到约每十二秒一帧**，`document.hidden` 恒为真。**「我看了几秒没动」什么都证明不了**。要验状态就读探针，要验时序就直接推累加器（工具④ 导出了 `__treeProbe()` / `__treeTick(dt)`，工具⑤ 照做）。
- **预览服务器**是 `.claude/launch.json` 的 `mathviz`（8777，根在主 checkout）。**需要浏览器验收的任务不要放进 worktree。** 端口可能已被别的 session 占着——那种情况下直接 `preview_start {url: "http://localhost:8777/..."}` 复用即可。
- **多 agent 共享浏览器会话，每次调用带显式 `tabId`**，先 `tabs_context`。探针第一条永远断言 `tool` 字段。
- **开发者的外接显示器是 30Hz**。一切按 `VizEngine.state.dt` 推进，**绝不按帧计数**。阶段 3b 正是在这里抓到「60fps 走 9 步/秒、30fps 走 10 步/秒」。
- **性能预算是每帧绘制耗时 ≤4ms**，不是 fps。注意其中约 2.8 ms 是全屏 canvas 的固定重绘成本，各工具共有；工具④ 自己的 JS 是 0.3 ms。强制光栅化每帧只做一次，探针开销单列。
- **两个 agent 不能同时改同一个文件**——同一 checkout 里是丢工作，不是 git 冲突。`git status --short` 后只暂存显式路径。

## 阶段 5 特有的坑（可预见的三个）

### 1. `STEP_LIMIT` 是架构上限，不是可调旋钮

实测（阶段 3b）：N 皇后 N=6 **4,674** 步、N=8 73,904 步；Warnsdorff 骑士巡游 5×5/6×6 3,523–5,670 步；**朴素回溯 DFS 骑士巡游 5×5 需 472,717 步、6×6 需 13,393,996 步**（GB 量级，装不下）。

§4⑤ 想让 `tourDFS` 与 `tourWarnsdorff` 并排对比「指数 vs 近线性」——**朴素 DFS 会撞上限**。阶段 4 已经证明了正确的处理方式：**把撞墙呈现成这一课的内容**（工具④ 深度 4 的 `tree` tab 就是这么做的，读数明说「超出 200,000 步上限，搜索没有跑完——这就是这一课，不是故障」）。照抄那套呈现。

### 2. 六道题全是递归，变量面板的正确性是它们的地基

阶段 3b 为此把 `locals` 从「深度窗口回放」推翻重做成「帧归属回放」，并改了 `interp.js` 一处入帧步批处理缺陷（调用方的 pending 会被刷到被调用方的帧上）。这些都已经在 main 上。

但**六道题的外层累加器**（`let solutions = 0` 这类）正是当初暴露问题的形状。写完第一道题就用 `Debugger.locals(cur, depth)` 逐帧核一遍，别等六道都写完。

### 3. §2.9 的挖空「比行为不比文本」

参考答案就是那份正在运行的源码本身，练习模式下那一段被换成占位符。**两者不可能漂移**——这与 §2.1「显示与执行同一份字符串」是同一条纪律，而 `ALGOS` 的内联机制（见上面第 1 条）正是它的载体。先把标记语法定下来，再写六道题。
